# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称

**Number Together** - 見えない誰かと、ひとつの数字をぴったり合わせる、みんなで遊ぶブラウザゲーム

### プロダクトコンセプト

- **URLを開くだけ**: ログインもインストールもいらない。PCでもスマホでも、URLを開けば、すぐ参加できる
- **見えない誰かを察する**: 数字は参加者全員で共有されていて、他の人も増やしたり減らしたりする。会話はできない。画面の向こうの動きを察しながら、みんなで目標に近づける
- **協力と欲のジレンマ**: +1を押すとポイントが貯まり、成功したときの個人報酬になる。「みんなで成功したい」と「自分は多く押したい」がぶつかる。押しすぎると、全員が失敗する
- **いつ来ても遊べる**: ゲームは常時開催され、数分で1回が終わる。途中からでも入れる

### プロダクトビジョン

画面に「+1」「−1」のボタンと、共有の数字がある。制限時間内に、その数字を、みんなで目標にぴったり合わせる。ルールは、これだけで、説明を読まなくても遊べる。

遊び方の核は、「見えない誰かの動きを察する」ことにある。数字の動き、グラフ、跳ねる小人から、他の人の意図を読む。最後の1分は、ポイントが3倍になる「倍増タイム」で、範囲の中で稼ぎたい気持ちと、安全に終わらせたい気持ちが、ぶつかる。

結果発表では、終了まで隠されていた全員のポイントが明かされ、「誰が欲張っていたか」が分かる。失敗しても、貯まっていたポイントが公開される。

遊ぶ人が少なくても成り立つよう、人間が5人未満のときは、性格を持つAIが加わる。公開は、itch.ioで行う。

将来は、人が実際に集まった場所で、テレビなどの大画面に数字を映し、各自が+1と−1のボタンだけの専用コントローラーを叩いて遊べるようにしたい。ハードウェアの設計は、今は含めないが、ソフトのインターフェースは、それに対応できるようにしておく。

### 目的

- 準備(アカウント登録、インストール、人集め)をなくし、URLを開くだけで、すぐ参加できるようにする
- 参加者が少ない時間帯でも、AIが加わることで、数字が動き、察し合う面白さが成り立つようにする
- 結果発表の「誰が欲張っていたか」で、遊んだあとも盛り上がるようにする
- 数分で1回が終わり、何度でも繰り返し遊べるようにする

## ゲームのルール

このゲームが実装するルールの正式な定義。機能要件の判定は、すべてこの定義に従う。

### 開催の流れ(常時開催)

- ゲームは常時開催し、「集合 → ゲーム → 結果発表」を繰り返す。1周は約6分(集合30秒、ゲーム5分、結果発表30秒。仮置きで、設定で変える)
- 集合中は、「次の開始まであと○秒」を表示する
- 集合中の画面では、集まった参加者を大きめに並べて、名前と称号を下に出す。空いている席、いまの目標と成功の範囲も出す。人が増えると、目標も上がる
- 人数がそろっていなくても、集合の時間がたったら、そこにいる人間とAIで始める(「20人そろったら早く始める」は、今は入れない)
- 人間が誰もいない回は、そのまま過ぎる。次に誰かが来たときに、時計をもとに、いまの段階から表示する
- 開始と終了は、時計だけで決める(例: 6分ごとに1周)。誰かが開始時刻を書き込むのではなく、全員の画面が、同じ時計をもとに、いまが第何回の、集合中・ゲーム中・結果発表中のどれかを計算する
- ゲームの途中から入ってもよい。ただし、終了の1分前からは入れず、次の回の集合を待つ
- ゲーム中に来て、全部の部屋が満員のときも、次の回の集合を待つ。ゲーム中に、新しい部屋は作らない。新しい部屋を作るのは、集合中のときだけ
- 待つ人には、待機画面を出す。ゲームの様子は見せない

### 準備

- 部屋に参加者が集まる。最大20人。20人を超えたら、裏側で次の部屋に割り振る。ユーザーには、部屋の番号を見せない
- 制限時間は5分(仮置き。3〜5分で試す)
- 共有の数字は0から始まる
- 目標の数は、参加人数(AIを含む)×200とする(仮置き。250も候補で、設定で変える)。成功の範囲は、目標の±10%とする(仮置き)。人数が多いほど、目標が大きくなり、範囲も広くなる
  - 例: 5人なら目標1000(範囲900〜1100)、10人なら2000(範囲1800〜2200)、20人なら4000(範囲3600〜4400)
- 途中から人が入ったときは、その人の分(200)だけ、目標が増える
- 途中で人が抜けても、目標は下げない(AIの数も変えない)。残った人が、たくさん押すことになる
- 人間の参加者が5人未満のときは、AIが加わって5人にそろえる(開始時点で決める。1人で遊ぶときは、人間1人とAI4人)

### 遊び方

- 全員が同じ数字を見ていて、「+1」「−1」のボタンで増やしたり減らしたりする
- 他の人が押した分も、すぐに自分の画面に反映される
- 数字の動き(上がったり下がったり、ぶれる様子)は、履歴グラフで見られる
- 「いまの数字」の上に、参加者(AIも含む)の小人が並び、いま押している人の小人が跳ねる。多くの小人が跳ねていれば、みんなが押していると分かる
- 跳ねるのは「いま押した」ことだけで、+1か−1かは分からない。他の人のポイントも見えない
- 会話やチャットはできない

### 成功と失敗

- 制限時間が終わった瞬間の数字が、目標±10%の範囲に入っていれば**成功**
- 中でも、目標と**ぴったり同じ**なら、特別ボーナス
- 範囲の外なら**失敗**
- 終了時刻より後の操作は受け付けず、データベースに残った最終値で判定する

### 個人ポイント

- +1を押すたびに、自分のポイントが貯まる(普通は1回につき1ポイント。倍増タイム中は、3倍になる)。ポイントの上限は、最初はなしで、後から付けられるよう、設定で変えられるようにしておく
- 成功したときだけ、貯まったポイントが報酬になる
- **終盤の倍増タイム**: 制限時間の最後の30秒〜1分(仮置き。最初は最後の1分)だけ、成功の範囲の中で押した+1は、ポイントが3倍になる(倍率と時間は、設定で変えられる)
- ぴったり成功のときは、ポイントにボーナスの倍率が掛かる(仮に×2)
- 失敗したときは、ポイントは報酬にならない(累計ポイントにも入らない)。参加したことだけ記録される。ただし、貯まっていたポイントは、結果発表で公開される
- −1を押しても、ポイントには何も影響しない
- 途中参加の人は、参加してから押した分だけを数える
- 自分のポイントは、ゲーム中も本人にだけ見える。他の人のポイントは、結果発表まで見えない

### AI参加者

- 人間の参加者が5人未満のとき、足りない人数をAIが埋めて、合計5人でゲームを始める
- AIの数は開始時点で決め、途中で人間が入ってきても変えない
- AIどうしは結託しない。それぞれ違う性格を持ち、その性格に従って、自分だけで+1や−1を押す
- 画面には、「がめついAI」「気まぐれAI」のように、性格の名前に「AI」を付けて表示する(人間とは見分けがつく)
- AIもポイントを数え、結果発表の一覧に、人間と一緒に載せる(AIのポイントも、結果発表まで見えない)
- AIの成績は、実績やランキングには記録しない
- 性格の例(たたき台):
  - **がめつい**: +1をよく押す。範囲の上端を越えそうになっても、なかなか手を止めない
  - **調整役**: 数字が範囲の外に出たら、戻す方向に押す。範囲の中では、あまり押さない
  - **ぴったり主義**: 目標とぴったりの数字を狙って、終盤に細かく+1・−1を押して合わせる
  - **気まぐれ**: +1と−1を、その場の気分で押す。たまに連打する
  - **ラストスパート**: 前半はほとんど押さず、倍増タイムが始まると、一気に+1を押す

### 結果発表

- 終了後に、全員のポイントを一覧で見せる(誰が欲張っていたかが、ここで分かる)
- 失敗したときも、貯まっていたポイントを一覧で見せる(「もらえなかったけど、欲張っていた」も分かる)

### このゲームで決めたこと

- **判定のタイミング**: 「途中で目標に達した時点で成功」ではなく、「時間が終わった瞬間」に判定する。終盤の駆け引きを生むため
- **許容幅**: ぴったりだけでなく、目標の±10%の幅を設ける。幅があると、終了間際に「あと少しなら押しても成功できる」余裕が生まれ、その余裕をポイント目当てで奪い合う駆け引きになる。ぴったりの達成感は、ボーナスで残す
- **−1は無料**: −1でポイントが減るようにすると、誰も−1を押さず、数字が上がり続けてしまう。そのため、−1はポイントに影響させない
- **ポイントの上限は、最初はなし**: −1が無料だと、+1と−1を交互に連打すれば、数字を動かさずにポイントだけ稼げてしまう。ただし、連打しても数字は動かないので、他の人の成功は邪魔されず、害はポイントの不公平だけ。友達や家族で遊ぶ程度なら問題が小さいため、最初は上限なしで始める。連打の稼ぎが目立つようなら、上限を付ける。上限は、設定で変えられるようにしておく
- **終盤だけ倍増する**: 範囲の中で押すほどポイントが増える仕組みを、時間の最初から入れると、みんなが範囲の中にとどまって稼ぐだけになり、成功しやすくなりすぎる。また、範囲の中で+1と−1を交互に押すだけで、数字を動かさずに3倍のポイントを貯められる。そこで、倍増するのは終盤だけにする。最後に、「範囲の中で稼ぐか、安全に終わらせるか」の駆け引きが集中する
- **目標は人数×200、範囲は±10%**: 1人あたり5分で、約200を足せば届く量にする(1人あたり0.7回/秒ほど。300にすると、1秒に1回押す計算になって忙しいため、減らした)。実際には、−1や押し合いがあるので、必要な押す回数は、これより多くなる。範囲を目標の±10%にすると、人数が増えても、範囲の割合は同じになる
- **途中参加で目標を上げる**: 途中から人が入ったら、その人の分(200)だけ目標を増やす。その方が盛り上がるため。目標が上がると、必要な押す回数が増えるので、ポイントも自然に多く入る。終了の1分前からは入れない(終盤に条件が動き続けるのを避けるため)
- **人が抜けても目標は下げない**: 残った人がたくさん押すことになり、慌ただしくて面白くなると考えるため
- **目標が上がるときは、「目標UP!」の吹き出しと、小人の召喚で見せる**: 入った人の小人が、画面の上からキラキラをまとって、ゆっくり、他の小人のいる地平線に降りてくる。同時に「目標UP!」の吹き出しを出す。上から降りてくる演出は、ゲーム中の途中参加だけ。集合中に入る人は、そのまま席に現れ、AIは、席にフェードインする
- **常時開催にする**: 後から入れる形にして、いつ来ても遊べるようにする。集合は30秒ほどにする(長いと待たされていると感じて離れる人が増え、短いと人が集まる前に始まるため)
- **開始は時計だけで決める**: 開始時刻を誰かが書き込む方式だと、書く人がいないと進行が止まる。時計だけで計算すれば、止まる心配がなく、いちばん簡単
- **部屋は、裏側で先着で割り振る**: 20人を超えたら次の部屋に割り振り、ユーザーには知らせない。20人の部屋1つより、10人の部屋2つのほうが、通信量も少なくて済み、遊びやすい。将来は、集合のときに、均等に分け直す案がある
- **待機中は、ゲームの様子を見せない**: 部屋がユーザーに見えないので、「どの部屋を見るか」が決められない。待機画面は、理由と次の回までのカウントダウンだけにする
- **AIで5人にそろえる**: 遊ぶ人が少なくても、数字が動いて、察し合う面白さが成り立つようにする。AIを結託させないのは、「見えない誰かの動きを察する」という遊びの核を残すため
- **AIは名前で見分けられるように表示する**: 性格が分かると、AIの動きは予想できるが、人間の動きは読めないので、察し合う面白さは残る
- **誰が押しているかを、跳ねる小人で見せる**: グラフには、+1と−1を差し引いた結果しか出ない。「押し合って数字が動かない」場合と「誰も押していない」場合が、同じ平らな線になる。小人なら、静かか、激しいかが雰囲気で分かる。+1か−1かは隠す
- **自分には、押した感覚を、視覚でそろえて返す**: 自分の小人の頭の上に「あなた」の吹き出しをいつも出し、押した瞬間に、小人が跳ね、「+1」の吹き出しが浮かび、「あなたのポイント」の数字が弾む。「+1」は、倍増タイム中も「+1」のままにする(「+3」にすると、全員で合わせている目標の数字が、3増えたように見えるため)
- **自分のポイントだけ見える**: 他の人のポイントが見えると、察する要素が減る。自分のポイントは、他の人の動きを読む手がかりにならないので、見せてよい。積み上がるのが見えると、押しすぎのジレンマが効く
- **失敗しても、ポイントは終了時に公開する**: 「もらえなかったけど、欲張っていた」が分かると、失敗したあとも話のネタになる
- **実績は、タップしたときの実績カードで見せる**: プレイ中は、実績による小人の見た目の違いは付けない。実績が分かるのは、部屋に集まっているとき(集合中)にする
- **途中参加の人には、入場の称号の帯を出す**: 「ぴったり王 ○○さん参戦!」のような帯。プレイ中は実績を見ない、という考えとは合わないが、途中参加の人だけに出してみる。あとから消すかもしれない

## 成功指標(KPI)

最初の版では、利用状況のアクセス解析は行わない。指標は、自動テストと、少人数のプレイテストで測る。

### プライマリーKPI

- **ルール判定の正しさ**: 「ゲームのルール」の各規則(成功・ぴったり・失敗の判定、倍増タイムの判定、ポイントの計算、目標と範囲の計算、途中参加、進行の切り替え)を検証する自動テストが、すべて合格する(最初の版の公開時)
- **取りこぼしがない**: 複数の参加者が同時に押しても、押した分がすべて数字に反映される(Emulator Suiteでの複数クライアントのテストで確認)
- **分かりやすさ**: ルール説明を読んでいない初めての人5人中4人以上が、手助けなしで、1回を最後まで遊べる(最初の版の公開前のプレイテストで測る)
- **テンポ**: 1周が、約6分(集合30秒、ゲーム5分、結果発表30秒)で回る

### セカンダリーKPI

- **手応え**: 成功率が、簡単すぎず難しすぎない。目安は、プレイテストで決める(遊びながら、目標や範囲の設定を調整する)
- **通信量**: 1回のプレイ(20人・5分)の通信量を、テストプレイで測り、無料枠(月10GB)の中で、何回遊べるかを見積もる。数字は、測ってから決める
- **無料枠の範囲**: 同時接続の上限(100)に、当面は届かない。届きそうになったら、見直す
- **動作環境**: 対応環境のPCとスマホの両方で、1回を最後まで遊べる(最初の版の公開時に手動確認)
- **「動きを減らす」設定**: 設定が有効なときも、すべての画面で、情報が欠けずに遊べる(手動確認)

## 機能要件

画面は、`docs/design/screens/README.md` と、見本(`docs/design/screens/screens/`)にある。

### コア機能(MVP)

#### 1. 共有の数字と、+1/−1ボタン

**ユーザーストーリー**:
プレイヤーとして、みんなで1つの数字を動かすために、ボタンを押すと、すぐに全員の数字が変わってほしい

**受け入れ条件**:

- [ ] 全員が同じ数字を見て、「+1」「−1」のボタンで増減させる
- [ ] 他の人の操作が、すぐに(数百ミリ秒以内に)自分の画面に反映される
- [ ] 同時に押しても取りこぼさない(サーバー側で加算する命令を使う)
- [ ] 自分の操作は、通信の返事を待たずに、すぐ画面に反映する
- [ ] −1と+1は、同じ大きさで、左右対称に並ぶ
- [ ] 連打は、短い間隔(0.2秒ほど)でまとめて送る
- [ ] ボタンは、スマホで素早く押しやすい大きさにする

**優先度**: P0(必須)

#### 2. ゲームの進行と判定

**ユーザーストーリー**:
プレイヤーとして、いつ来ても遊べるように、集合・ゲーム・結果発表が、自動で繰り返してほしい

**受け入れ条件**:

- [ ] 「集合 → ゲーム → 結果発表」を繰り返す。長さは、集合30秒、ゲーム5分、結果発表30秒(仮置き。設定で変える)
- [ ] 開始と終了は、時計だけで決める。全員の画面が、同じ時計から、いまの段階を計算する。端末の時計のずれは、データベースのサーバー時刻との差を測って補正する
- [ ] 集合中は、「次の開始まであと○秒」を表示する
- [ ] 時間が終わった瞬間の値で、成功・ぴったり成功・失敗を判定する
- [ ] 終了時刻より後の操作は、データベースのセキュリティルールで受け付けない
- [ ] 目標の数、成功の範囲、残り時間を画面に表示する。残り時間は、グラフの左上に出す
- [ ] 人間が誰もいない回は、そのまま過ぎる
- [ ] ゲーム中の合図の演出を出す(画面の見本は`screens/04-start.html`、`screens/07-x3-start.html`、`screens/08-ten-seconds.html`、`screens/09-end.html`):
  - 「3・2・1・スタート!」: 集合からゲームに変わる瞬間に、画面を暗くして、大きな数字を1秒ずつ出す
  - 「×3 タイム スタート!」: 倍増タイムに入る瞬間に、赤いトゲトゲの「×3 タイム!」と「最後の1分は、ポイントが3倍!」を出す
  - 終了10秒前: 画面のふちを赤く点滅させ、グラフの左上の残り時間を強調する。大きなカウントダウンの数字は出さない(グラフが隠れるため)
  - 「終了!」: 時間切れの瞬間に、黒い帯が斜めに入って「終了!」を出し、「判定しています」と示す
- [ ] 「動きを減らす」設定のときは、合図の演出の動きをやめて、静止した表示にする

**優先度**: P0(必須)

#### 3. 個人ポイント

**ユーザーストーリー**:
プレイヤーとして、押すことに手応えを感じるために、自分が貯めたポイントを見たい。また、他の人の動きを読む楽しみを残すために、他の人のポイントは、最後まで隠してほしい

**受け入れ条件**:

- [ ] +1を押すたびに、自分のポイントが貯まる(普通は1回につき1ポイント)
- [ ] −1を押しても、ポイントには何も影響しない
- [ ] 終盤の倍増タイム(最後の1分。仮置き)は、成功の範囲の中で押した+1のポイントを3倍にする。倍率と時間は、設定で変える
- [ ] 範囲の中で押したかどうかは、押した瞬間の数字で判定する
- [ ] ポイントの上限は、最初はなし。設定で、後から付けられる。倍増タイムだけに、上限を付けることもできる
- [ ] 成功したときだけ、貯まったポイントが報酬になる。ぴったり成功のときは、ボーナスの倍率が掛かる(仮に×2)
- [ ] 失敗したときは、ポイントは報酬にならず、累計ポイントにも入らない。参加したことだけ記録される
- [ ] 途中参加の人は、参加してから押した分だけを数える
- [ ] 自分のポイントは、「あなたのポイント」として、ゲーム中も本人にだけ見せる(黒い表示板。ボタンと似せない)。押した回数そのものは、見せない
- [ ] 他の人のポイントは、結果発表まで、データベース上でも読めない場所に置く
- [ ] 自分が押すたびに、「あなたのポイント」の数字が、ぽんと弾む

**優先度**: P0(必須)

#### 4. 結果発表

**ユーザーストーリー**:
プレイヤーとして、遊んだ結果を楽しむために、成功したか、ぴったりだったか、ポイントがどうなったか、誰が欲張っていたかを見たい

**受け入れ条件**:

- [ ] 結果は「ぴったり」「成功」「失敗」の3通りで、お祝いの強さを変える(ぴったり: 赤いトゲトゲの見出しときらめき、成功: 緑のトゲトゲで控えめ、失敗: 飾りなしで「残念…」)
- [ ] 最終の数字、目標、成功の範囲、範囲内かどうかを表示する。失敗のときは、「あと○○足りなかった」を出す
- [ ] あなたのポイントを表示する。ぴったり成功なら、ボーナスの倍率と合計も出す。失敗のときは、「貯まっていたポイント」を取り消し線で出し、「もらえなかった」と示す
- [ ] 累計ポイントが、どう変わったかを出す(失敗のときは変わらない)
- [ ] 全員のポイントを一覧で見せる(上位7人と、自分の行を強調して出す。自分が圏外のときは、「・・・」で区切って、自分の行を下に出す。失敗のときも、貯まっていたポイントを見せる。AIも載せる)
- [ ] 次の回までの、カウントダウンを続けて出す
- [ ] 画面の見本は、`screens/10-result-perfect.html`(ぴったり)、`screens/11-result-clear.html`(成功)、`screens/12-result-fail.html`(失敗)

**優先度**: P0(必須)

#### 5. 履歴グラフ

**ユーザーストーリー**:
プレイヤーとして、他の人の動きを察するために、数字がどう動いてきたかをグラフで見たい。また、あとどれくらいで終わるか、いつボーナスの時間になるかも、グラフで分かるようにしてほしい

**受け入れ条件**:

- [ ] 数字の動きを、ゲーム中にグラフで見せる。最初は、各自のブラウザが受け取った数字を、その場でグラフにする(データベースには保存しない)
- [ ] 途中参加の人は、参加した時点からのグラフになる
- [ ] 縦軸には、目標の±10%の範囲を、緑の帯と数字(例: 3600・4000・4400)で出す。目標の線は、点線にする
- [ ] 横軸は時間。グラフの右から1/3あたりを「いま」とし、点線と丸印で示す。線は「いま」までを描き、それより右は未来として、線を引かない
- [ ] 未来の部分に、最後の1分の「×3 ボーナス」の斜線の帯と、「終了」の線(「終」と「了」の札の間を、線が通る)を出す。残り時間が減ると、帯と終了の線が「いま」に近づいてくる(未来の長さは、約60秒分で仮置き)
- [ ] 残り時間は、グラフの左上に、「残り 0:48」のように出す。残りが10秒を切ったら、赤い背景で強調して脈動させる
- [ ] 数字の右に、緑の「範囲内!」の札を出す(範囲の外のときは、色と文言を変える)
- [ ] 画面の見本は、`screens/05-play.html`(プレイ中)と`screens/08-ten-seconds.html`(終了10秒前)

**優先度**: P0(必須)

#### 6. ログイン不要の参加と実績

**ユーザーストーリー**:
プレイヤーとして、すぐ遊び始めるために、ログインなしで参加したい。それでも、自分の名前とキャラクターと、実績が、他の人に見えるようにしたい

**受け入れ条件**:

- [ ] 匿名認証で、ブラウザを開いただけで、IDを割り当てる
- [ ] 最初の1回だけ、名前とキャラクターを選ぶ画面を出す(画面の見本は`screens/01-setup.html`)
- [ ] 名前は、ほかの人にも見える。長さは、画面に表示したときの幅が同じくらいになるように決める。日本語(全角)なら6文字、英数字(半角)なら12文字まで。混ざっているときは、全角を2、半角を1と数えて、合計12まで。入力欄には、「6 / 12」のように、数えた量を表示する
- [ ] キャラクターは、髪型・服の色・小物を組み合わせて選ぶ。「おまかせ」で、ランダムに決めることもできる
- [ ] ブラウザのデータを消したり、ほかの端末で開いたりすると、別の人として扱われて、実績は引き継がれないことを、一言添える
- [ ] 実績として、参加回数・成功回数・ぴったり成功の回数・累計ポイントを保存し、他のプレイヤーからも見えるようにする
- [ ] 自分の画面を用意する: 自分の小人と名前と称号、実績、「名前・キャラをかえる」ボタン、「動きをへらす」のスイッチを出す(画面の見本は`screens/18-me.html`)
- [ ] AIの成績は、実績に記録しない

**優先度**: P0(必須)

#### 7. 部屋と人数による調整

**ユーザーストーリー**:
プレイヤーとして、人数に合った難しさで遊ぶために、人数に応じて目標が変わってほしい。途中から入っても、遊べるようにしてほしい

**受け入れ条件**:

- [ ] 1部屋の最大人数は20人。20人を超えたら、裏側で次の部屋に割り振る(先着で埋める)。ユーザーには、部屋の番号も、部屋の移動も、見せない
- [ ] 同時に何人かが入ろうとしても、20人を超えない(データベースの条件付きの書き込みで、入室を決める)
- [ ] 新しい部屋を作るのは、集合中のときだけ。ゲーム中に全部の部屋が満員なら、待機画面を出して、次の回の集合を待ってもらう
- [ ] 参加人数(AIを含む)×200を目標とし、目標の±10%を成功の範囲とする
- [ ] 途中から人が入ったら、その人の分(200)だけ、目標を増やす。途中で人が抜けても、目標は下げない
- [ ] 終了の1分前からは、途中参加できない(待機画面を出す)
- [ ] 目標が上がったときは、「目標UP!」の吹き出しを出し、グラフの目標線と範囲の帯が、少し上に動く
- [ ] 目標と範囲の計算は、画面の部品の中に書かず、ルールの部分に置く(全員が同じ目標を見られるようにするため)

**優先度**: P0(必須)

#### 8. PCとスマホの両方で遊べる

**ユーザーストーリー**:
プレイヤーとして、手元の端末で気軽に遊ぶために、PCでもスマホでも、同じように遊べるようにしてほしい

**受け入れ条件**:

- [ ] 幅390pxのスマホの縦画面を基準にする。PCで開いたときは、中央に、同じ幅で表示する
- [ ] 幅360px以上の画面で、横スクロールなしで、すべての画面が表示される
- [ ] ボタンは、スマホで素早く押しやすい大きさにする
- [ ] アプリストアでの配信は行わず、ブラウザで遊ぶ形とする
- [ ] 端末の「動きを減らす」設定(`prefers-reduced-motion`)のときは、動きをやめて、静止した表示にする

**優先度**: P0(必須)

#### 9. 通信量の計測(テスト用)

**ユーザーストーリー**:
開発者として、無料枠の中で遊べるかを判断するために、1回のプレイの通信量を測りたい

**受け入れ条件**:

- [ ] 受け取った更新の回数とバイト数を、ブラウザで数えて、プレイの終了時に、コンソールや画面の隅に表示する
- [ ] テストプレイで、1回のプレイの通信量を調べるために使う。公開前に外す(または、非表示にする)
- [ ] 通信量の測定は、本番のデータベースにつないで行う(Emulator Suiteでは、実際の通信量は測れない)

**優先度**: P0(必須)

#### 10. AI参加者

**ユーザーストーリー**:
プレイヤーとして、人が少ない時間帯でも遊べるように、AIが加わってほしい

**受け入れ条件**:

- [ ] 人間が5人未満のとき、AIが加わって5人にそろえる
- [ ] AIはそれぞれ性格を持ち、結託せずに、自分の性格に従って+1・−1を押す
- [ ] 集合中の画面で、AIは、参加者が入る席に、フェードインして加わる(上から降りてくる演出は使わない。「人が少ないので、AIが3人 加わるよ」と書く。画面の見本は`screens/03-lobby-ai.html`)
- [ ] 画面には「がめついAI」のように、性格の名前+AIで表示する。AIは、ロボットの姿で、胸のランプの色で性格が分かる
- [ ] 反応には、少し遅れとばらつきを持たせて、人間より正確すぎないようにする
- [ ] AIの操作は、参加者の1人のブラウザ(AI担当)が、代わりに送る。担当が抜けたら、次に古い参加者が引き継ぐ
- [ ] 結果発表の一覧に、AIのポイントも載せる

**優先度**: P0(必須。遊ぶ人が少ない間は、これがないと遊びにくいため、最初の版に入れる)

#### 11. 参加者の小人(誰が押しているかの表示)

**ユーザーストーリー**:
プレイヤーとして、みんなが押しているか、静かかを雰囲気で知るために、参加者が跳ねる様子を見たい

**受け入れ条件**:

- [ ] 「いまの数字」の上の舞台に、参加者の小人を並べ、いま押している人の小人が跳ねる
- [ ] 跳ねる高さと速さは、直近の押し方の強さに合わせる
- [ ] +1か−1かは分からない。他の人のポイントも出さない
- [ ] 自分の小人の頭の上に、ピンクの小さな吹き出しで「あなた」と、いつも表示する(舞台の上にはみ出して出し、跳ねても、ぶつからないようにする。自分の小人は、いちばん手前に出す)。一人ひとりの小人は、髪型・服の色・小物でも見分けられるようにする
- [ ] 自分が押したときは、通信を待たずに、小人が跳ね、頭の横に小さな「+1」の吹き出しが浮かんで消え、「あなたのポイント」の数字が弾む。吹き出しは、倍増タイム中も「+1」のままにする(「+3」にすると、目標の数字が3増えたように見えるため)。−1のときは「−1」を出す(仮)。他の人には出ない
- [ ] 20人のときは、1列で、隣どうしが体の約1/3ずつ重なるように並べる(奥と手前で、立つ位置を少しずらす)
- [ ] 名前は、人数が多いときは小人をタップしたときに出し、少ないときは常に表示する
- [ ] 小人をタップすると、実績カードが出る(名前、称号、参加回数、成功回数、ぴったり成功の回数、累計ポイント)。ほかをタップすると閉じる(画面の見本は`screens/13-achievement-card.html`)
- [ ] 途中から人が入ったときは、その人の小人が、画面の上から、光の柱の中を、キラキラをまとって、ゆっくり地平線に降りてくる(召喚の演出)。同じタイミングで、「目標UP!」の吹き出しを出す
- [ ] 称号のある人が入ったときは、「ぴったり王 ○○さん参戦!」のような帯も出す(あとから消すかもしれない。画面の見本は`screens/06-play-late-join.html`)
- [ ] 「動きを減らす」設定のときは、跳ねずに色が光る。召喚は、降りてくる動きをやめて、その場に現れて光る
- [ ] 「いま押した」の合図は、1人につき1秒に1回までにまとめる

**優先度**: P0(必須)

#### 12. 言語切り替え(日本語・英語)

**ユーザーストーリー**:
日本語を読めないプレイヤーとして、このゲームで遊ぶために、画面を英語に切り替えたい

**受け入れ条件**:

- [ ] 画面にある切り替えボタンを押すと、日本語と英語が切り替わる。ボタンには、切り替えた先の言語名を表示する(今が日本語なら「English」、今が英語なら「日本語」)
- [ ] 切り替えボタンは、どの画面でも、同じ場所(右上)にある。プレイ中の画面では、グラフや小人を隠さない小ささにする
- [ ] ゲームの画面にあるすべての文言(見出し、ボタン、ラベル、札、吹き出し、メッセージ、演出の文字、称号、AIの名前、注意書き)が、切り替えの対象になる。他のプレイヤーが付けた名前は、そのまま表示する
- [ ] ゲームの途中で切り替えても、進行中の状態(数字、ポイント、残り時間、参加者)はそのままで、文言だけが切り替わる
- [ ] 切り替えは、自分の画面だけに効く。他のプレイヤーには、影響しない
- [ ] 英語にしても、文字が、札・ボタン・吹き出し・カードの枠からはみ出さない
- [ ] 選んだ言語は、ブラウザに覚えておき、次に開いたときも、同じ言語で始まる
- [ ] 初めて開いたときの言語は、ブラウザの言語設定に合わせる(日本語なら日本語、それ以外は英語。仮)
- [ ] すべての文言を、言語ごとの文言の一覧に分けて書き、画面の部品に、直接書かない

**優先度**: P0(必須。文言を、あとから一覧に分けると、全画面の作り直しになるため、最初の版から入れる)

### 将来的な機能(Post-MVP)

#### 16. ルールの発展

ボタンに違いを持たせる(+10や+50だけを持つ人)、目標を一部の人だけが知る、邪魔をする役、目標が動く、維持する時間で競う、チーム対抗、スタンプだけ許す、秘密のラッキーナンバー、賭け、など。遊んでみて、必要なものを選ぶ。

**優先度**: P2(できれば)

#### 17. 不正対策

成功の判定とポイントの加算を、サーバー側の関数(Cloud Functions)で行う。有料のBlazeプランが必要。不特定多数に公開して、ランキングを競わせるようになったら、取り組む。

**優先度**: P2(できれば)

#### 18. 端末の引き継ぎ

Googleログインなどを、任意で追加して、別の端末でも、同じ実績を使えるようにする。

**優先度**: P2(できれば)

#### 19. イベント用の大画面モード

今の数字とグラフだけを大きく映す、観戦用の画面。横長の画面用に、レイアウトを別に作る。

**優先度**: P2(できれば)

#### 20. 専用コントローラーと大画面(将来)

人が実際に集まったときに、画面はテレビなどの大画面に映し、各自の手元には、+1と−1のボタンだけの専用コントローラーを配って、叩いて遊べるようにする。ハードウェアの設計は、今は含めない。今は、ソフトのインターフェースを、それに対応できる形にしておく(画面と操作を分ける、操作の形式をそろえる、ルールを画面から切り離す、席の仕組みを作る、など。詳しくは `docs/architecture.md`)。

**優先度**: P2(できれば)

## 非機能要件

### パフォーマンス

- 他の人の操作の反映: 目安として、数十〜数百ミリ秒(実際の値は、回線や端末による)
- 自分の操作は、サーバーの返事を待たずに、すぐ画面に反映する
- 連打は、0.2秒ほどまとめて送る。「いま押した」の合図は、1人につき1秒に1回まで
- 小人の跳ねる動きや、召喚の演出は、なめらかに(目標60fps)表示する
- 初回表示: 一般的なモバイル回線で、3秒以内に遊べる状態になる(測定方法は `docs/architecture.md`)

### ユーザビリティ

- ルール説明を読まなくても、遊べる(ボタンは2つ、目標は1つ)
- 「範囲内!」の札や、グラフの帯など、成功の状態が、色だけに頼らず、文字や形でも分かる
- 動きを減らす設定(`prefers-reduced-motion`)が有効なときは、動きをやめて、静止した表示にする
- 画面の文言は、短く、やさしい言葉にする。日本語と英語の両方で、そうする
- 画面の言語は、日本語と英語。画面の切り替えボタンで、切り替える
- 待つ人、通信が切れた人、入れない人にも、何が起きているかと、いつ遊べるかを伝える

### 信頼性

- ルール判定(成功・ぴったり・失敗、倍増タイム、ポイント、目標と範囲の計算)は、「ゲームのルール」の定義と、完全に一致する(自動テストで確認)
- 同時に押しても、取りこぼさない(Emulator Suiteでの複数クライアントのテストで確認)
- 進行は、時計だけで決まるので、誰かが抜けても止まらない
- AI担当が抜けても、次の参加者に引き継がれ、AIの操作が止まらない

### セキュリティ

- 個人情報を、一切収集しない。名前は、本人が選んだニックネームだけ(全角6文字、半角12文字まで)
- 匿名認証を使い、メールアドレスなどは扱わない
- データベースのセキュリティルールで、自分のIDのデータだけ書き込めるようにする。実績は誰でも読める。ポイントは、結果発表まで、他の人が読めない場所に置く。終了時刻より後の操作は受け付けない
- FirebaseのAPIキーは、ブラウザ側のコードに入る前提とし、守りは、セキュリティルールで行う
- 外部のトラッキングやスクリプトを読み込まない(書体の読み込みは除く)
- 最初の版は、ポイントや成功回数を、ブラウザから書き込む。詳しい人は、水増しできる。公開が広がって、ランキングを競うようになったら、サーバー側に切り替える(P2「不正対策」)

### スケーラビリティ

- 1部屋20人まで。20人を超えたら、裏側で次の部屋に割り振る
- 無料プランの同時接続は100まで。当面は、これで足りる。届きそうになったら、有料プラン(Blaze)に切り替える
- 全員の連打が全員に配信されるので、人数が増えるほど通信量が急に増える(人数が2倍で、おおよそ4倍)。連打をまとめて送り、合図を1人1秒に1回までにして抑える
- 将来の専用コントローラーと大画面に備えて、画面と操作を分け、操作の形式をそろえ、ルールを画面から切り離す。席(プレイヤー枠)を、ブラウザの匿名IDとは別に持つ

### 対応環境

- 公開先: itch.io(ブラウザゲームとして、zipでアップロードする)
- PC: 最新版の Chrome / Edge / Firefox / Safari
- スマホ: iOS Safari・Android Chrome の最新版
- 画面幅360px以上(幅390pxの縦画面を基準にする)
- 言語: 日本語・英語
- itch.ioのiframeの中で動くこと(iframeの中でのID保存が、Safariなどでうまくいくかは、公開前に実機で確認する)

## スコープ外

明示的にスコープ外とする項目(最初の版):

- 友達と同じ部屋で遊ぶ機能(部屋の番号を見せないため。必要になったら、部屋の番号を共有する機能を足す)
- 「20人そろったら早く始める」
- 大画面モード、専用コントローラー
- ルールの発展(ボタンの違い、邪魔役、チーム対抗など)
- サーバー側の不正対策、端末の引き継ぎ
- AIの小人をタップしたときの、性格の紹介
- 名前の入力エラーの表示
- 日本語・英語以外の言語
- スマホアプリ化(App Store・Google Playでの配信)
- アクセス解析

## 決定事項(アイデアメモから)

- **公開先**: itch.io
- **バックエンド**: Firebase Realtime Database + 匿名認証(サーバー側のプログラムは書かない)。データベースの場所は、シンガポール
- **進行**: 時計だけで決める
- **AIの動かし方**: 最初は、参加者の1人のブラウザ(AI担当)が、代わりに操作する
- **書き込み**: 最初は、ブラウザから書き込む。不正対策は、あとで
- **言語**: 日本語と英語に対応する。画面の切り替えボタンで、切り替える。最初の版から入れる
- **英語の文言**: 日本語の文言をもとに、Claude Codeが作る。短く、やさしい言葉にする
- **名前の長さ**: 画面に表示したときの幅が同じくらいになるように、日本語(全角)6文字、英数字(半角)12文字まで。混ざっているときは、全角を2、半角を1と数えて、合計12まで
